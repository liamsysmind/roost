# Working on roost

`roost` is a single Go binary that serves a web UI: terminal + file tree +
Activity panel (Claude Code / Codex) + push notifications. It's designed for
SSH-tunnel-first deployment on a personal dev box. Single-user; not
multi-tenant.

## Layout

```
cmd/roost/main.go             # CLI entry: serve / setup / hook-info / notify-stop / version
internal/
  auth/        # bcrypt + cookie session middleware
  config/      # TOML loader (~/.config/roost/config.toml)
  session/     # tmux-backed PTY sessions
    log.go        # append-only disk log per session (unbounded scrollback)
    session.go    # Session: owns PTY+log, broadcasts to attached clients
    client.go     # Client: WS conn + buffered out queue (drops slow consumers)
    manager.go    # Manager: GetOrCreate / Rename / Delete / PaneInfo / GC loop
    handler.go    # GET /ws/terminal[/{id}] WebSocket handler
  fs/          # rooted filesystem API
    fs.go         # path-traversal-safe operations
    handler.go    # /api/fs/* routes (list, download, upload, mkdir, rename, remove)
  ai/          # agent state readers (Claude Code + Codex)
    ai.go         # ~/.claude/projects JSONL parser, token aggregation (no USD)
    codex.go      # ~/.codex/sessions rollout resolver, keyed by session_meta cwd
    handler.go    # /api/ai/usage, /api/ai/sessions, /api/ai/active
  notify/      # in-process pub/sub
    notify.go     # broadcast + slow-consumer drop policy
  server/      # HTTP wiring
    server.go     # routes + auth middleware + handlers for sessions/notify/SSE
    loginlimit.go # per-IP exponential backoff on failed logins
    web/          # embedded SPA (//go:embed all:web)
      *.html      # home / login / index pages
      *.js        # app.js (terminal), fs.js (tree), ai.js (Activity panel),
                  # sessions.js, home.js, notify.js + notify-worker.js, toast.js
      vendor/     # gitignored; fetched by scripts/fetch-vendor.sh — xterm.js
                  # 5.5 + addon-fit/webgl/search, marked, highlight.js
scripts/fetch-vendor.sh        # downloads vendor/ and patches xterm.js
docs/cloudflare.md             # Cloudflare Tunnel + Access deployment
dist/                          # generated by `make cross` (gitignored)
  systemd/roost.service
  launchd/com.liamsysmind.roost.plist
Makefile                       # build / cross / dev / install
```

## Build & run

```
make           # builds ./roost with version baked in via ldflags
make cross     # linux+darwin × amd64+arm64 → dist/
make dev       # kill old, build, run in foreground
```

Setup once:

```
echo 'PASSWORD' | ./roost setup --password-stdin
```

Generates `~/.config/roost/config.toml` with bcrypt hash, session secret, and
**hook secret** (used by Claude Code Stop hooks to POST notifications).

Run:

```
./roost serve
# Listens on 127.0.0.1:8080. Access via SSH tunnel — or set
# addr = "0.0.0.0:8080" in config.toml (or front with `tailscale serve`)
# for cross-device access from phones / tablets.
```

## Design philosophy — non-negotiable

**roost is single-user per instance, forever.** If multiple people share a
machine, each runs their own `roost serve` on a different port with their
own `~/.config/roost/` and `~/.local/share/roost/`. UNIX UIDs handle the
isolation; we do not.

Do not add user databases, role-based auth, per-user data partitions, or
"workspace" sharing within a single roost process. Anything that smells
like "let's make roost serve multiple identities" should instead push that
concern up to the deployment layer (a separate hub component, reverse
proxy, etc.) rather than into this codebase.

## Key design decisions

- **tmux is required.** Each session is `tmux new-session -A -s {id}`. Shell
  survives WS disconnect, server restart, idle GC. roost refuses to start if
  tmux isn't in PATH.
- **Tmux is invisible to the user.** `roost-tmux-uid{N}.conf` (written to a
  temp dir at startup; the UID is in the name so two people running their
  own roost on one host don't collide on file ownership) sets
  `status off`, `unbind-key -a`, `escape-time 0`, `destroy-unattached off`.
  No prefix key, no status bar, no nesting warnings.
- **Scrollback needs three settings, not one.** `history-limit 50000` gives
  the tmux pane somewhere to hold scrolled-off lines; `terminal-overrides
  smcup@:rmcup@` stops tmux entering the alt buffer on attach (the alt buffer
  has no scrollback, and xterm.js then turns wheel events into ↑/↓ keystrokes);
  `indn@:rin@` forces individual line feeds instead of CSI Pn S/T, which
  xterm.js implements per spec by DROPPING the scrolled lines. Apps that use
  alt-screen themselves (vim, less) still work — tmux translates. See the
  comment block above `roostTmuxConf` before touching any of these.
- **Disk log is the source of truth for scrollback.** Per-session
  `~/.local/share/roost/sessions/{id}.log` is append-only and effectively
  unbounded. `replay_kb` only caps how much of the tail is replayed on attach.
- **Multi-tab broadcast.** Two browser tabs on the same `/s/{id}` see the
  same screen; bytes are fanned out to every attached client.
- **Path traversal is rejected at API boundary.** `fs.API.resolve()` keeps
  every operation under `Root` (default $HOME). Session IDs are validated
  against `[A-Za-z0-9._-]{1,128}` before touching disk.
- **File tree follows cwd via tmux.** The frontend polls
  `GET /api/sessions/{id}/cwd` every 2s, which shells out to
  `tmux display-message`. No shell integration required. Paths outside
  `[fs] root` are ignored silently.
- **Which agent is running is inferred from the process tree.** That same
  poll returns `{cwd, command, app}` — one `display-message` asks for
  `pane_current_path`, `pane_current_command` and `pane_pid`;
  `classifyPaneTree` walks the descendants via `ps` (BSD+GNU flags, not
  /proc, so Linux and macOS share one code path) and reports `claude`,
  `codex`, or `""`. A bare `node script.js` deliberately doesn't match. That
  verdict routes `/api/ai/active` to the right store — `~/.claude/projects`
  and `~/.codex/sessions` share no metadata, so "scan both and merge" is not
  an option — and it is what the notification gate checks.
- **Hook secret is the trapdoor.** `POST /api/notify` accepts the
  `X-Roost-Hook-Secret` header instead of a cookie so local hooks can push
  without a UI session. The hook is a one-line `roost notify-stop`
  invocation (printed by `roost hook-info`); the binary reads Claude
  Code's Stop JSON from stdin, extracts cwd, and POSTs.
- **xterm.js is patched at fetch time, not edited in place.** `vendor/` is
  gitignored, so a direct edit there vanishes on a fresh clone with no error.
  `scripts/fetch-vendor.sh` applies two composition fixes after downloading
  the bundle; each anchor must match exactly once or the fetch fails, so an
  xterm.js bump breaks the build instead of silently restoring the bug.
  Re-running `make` does NOT re-apply them — the Makefile only fetches when
  `vendor/xterm.js` is absent, so delete it first to test a patch change.
- **One SSE socket per browser, not per tab.** `notify-worker.js` is a
  SharedWorker owning the single `/api/notify/stream` EventSource and
  broadcasting to every tab's port. Without it a few terminal tabs exhaust
  Chrome's 6-connections-per-origin HTTP/1.1 budget; the SSH-tunnel
  deployment has no TLS, so h2 can't raise that cap.
- **Stop-hook gating is client-side.** Server fans out every notification;
  notify.js only fires the OS toast when the tab matches all of: same
  cwd as the event, hidden/unfocused, `currentApp === 'claude'`, idle
  longer than `[notify] idle_alert_after` (default 30s). Events without
  a `cwd` (legacy snippets, manual UI POSTs) bypass the gate.

## Code conventions

- **Frontend is vanilla JS** under `internal/server/web/`. No build pipeline.
  Each page loads only the scripts it needs — `/s/{id}` takes `app.js`,
  `fs.js`, `ai.js`, `sessions.js`, `toast.js`, `notify.js`; the home page
  takes `home.js`, `toast.js`, `notify.js`. Stay this way until a feature
  genuinely justifies introducing Svelte / a bundler.
- **HTTP methods use Go 1.22 patterns**: `mux.HandleFunc("GET /path", h)` and
  `r.PathValue("id")`. Don't reach for chi unless we need middleware grouping.
- **Errors flow up with `%w` wrapping** and become user-readable HTTP error
  bodies. Don't log-and-continue silently in API handlers.
- **Each new HTTP handler must respect the auth middleware.** Public routes
  go into `isPublicPath()`. Hook-secret-bypass paths are explicit in
  `authMiddleware` and only for `POST /api/notify` so far.
- **The password is the only wall in front of a shell.** `POST /login` runs
  through `loginLimiter`: 5 free failures per client IP, then an exponential
  lockout capped at 15 min. Keyed per IP so a flood from one source can't
  lock the real user out from another; behind Cloudflare the key is
  `CF-Connecting-IP`. Don't add another credential-checking path that skips it.
- **No comments stating the obvious.** Comment WHY a non-obvious choice was
  made (e.g. why `=ID` doesn't work with `tmux display-message`).
- **Prove a frontend change reached the browser before judging it.** Every
  asset is served as `?v={{VERSION}}`, and `git describe --tags --dirty`
  returns the same string across every dirty rebuild — so plain `make` leaves
  the browser on the cached copy no matter how often you reload. Build with a
  unique version while the tree is dirty:
  `make build VERSION="v0.5.1-dev$(date +%s)"` (or `make dev`). The WebSocket
  auto-reconnect hides this: restarting roost respawns the server-side tmux
  clients, so everything looks fresh while the page keeps its old JavaScript.
  A fix that "didn't work" has usually not run yet.
- **Docs and code must not drift apart.** Rules written up elsewhere — the
  CoStruct IME spec, README, this file — describe what the code actually does.
  When a review or any outside source suggests a rule, check it against the
  implementation before adopting it, and change both together or neither.
  Adopting a reviewer's rule without that check is how this file ends up
  describing software that doesn't exist.

## Testing

`go test ./...` covers the parts where a wrong answer is silent rather than
loud. All three are table-driven; follow the pattern when adding more:

- `internal/fs/fs_test.go` — path-traversal containment
- `internal/ai/filter_test.go` — which JSONL entries count as a human prompt
- `internal/session/lastused_test.go` — last-input vs. last-output ordering

There is no HTTP-level test suite; those paths are still smoke-tested by hand:

- Curl + cookie jar (`/tmp/cj`) for HTTP routes
- Tiny Go WebSocket client in `/tmp/wstest*/` for `/ws/terminal/{id}`
- `tmux send-keys` + `display-message` for verifying tmux backend
  independently of WS framing races

## What's intentionally not done

- **No editor.** roost surfaces files for transfer; users edit inside the
  terminal with whatever editor they brought.
- **No multi-user.** One password, one user. Reverse-proxy if you need more.
- **No Svelte / no build step.** Vanilla JS until it stops fitting.
- **No public-internet listener.** Loopback by default. SSH tunnel from a
  laptop, `tailscale serve` from phones; flip `addr` to `0.0.0.0` only if
  you intentionally want every interface (LAN included) to see it. Public
  HTTPS is a deployment-layer concern, not a roost feature: a Cloudflare
  Tunnel reaches the loopback listener with Access/SSO in front of the
  password (`docs/cloudflare.md`), so the host still opens no ports.
- **No tmux status bar / prefix key.** Tmux is plumbing, not UI surface.

## When extending

- Adding an API endpoint → wire it in `internal/server/server.go`'s
  `setupRoutes`; if it needs to bypass auth, add to `isPublicPath` or the
  hook-secret branch in `authMiddleware`. Re-confirm path-traversal containment
  if filesystem-adjacent.
- Adding a frontend page → new HTML in `internal/server/web/`, register a
  `GET /your-page` handler that serves it. Add to the static handler if it
  needs JS/CSS siblings.
- Adding a config knob → extend `internal/config/config.go`'s struct + the
  matching default in `Load()` / `runSetup()`. Document in README's config
  section. Don't add CLI flags for the same setting unless overriding per-run
  makes sense.
